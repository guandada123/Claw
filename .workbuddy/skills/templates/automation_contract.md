# 🔧 自动化定义契约（Automation Contract）

> 对齐「WorkBuddy 高阶玩法」模块4：自动化矩阵先画流程图，每个节点单独跑通再串联。
> 每个自动化在创建/大改时，必须在本契约中填齐五要素。缺任一要素视为未定义完整。

---

## 一、五要素模板（必填）

```
【触发条件 Trigger】
- 类型：⏰时间(RRULE) / 📡事件(webhook) / 🔀条件(上游结果)
- 具体：FREQ=WEEKLY;BYDAY=MO;BYHOUR=9  （时间类必须单 BYHOUR，禁多值）
- 宿主：cwds=/Users/guan/WorkBuddy/Claw 或托管项目工作区

【输入 Input】
- 数据源：qt.gtimg.cn / Wind MCP / 本地 portfolio.json / 公众号 RSS ...
- 前置依赖：preamble.sh / 本地代理 :9999 / 飞书 lark-cli
- 失败降级：源不可达时走何降级路径（如 Wind→腾讯）

【输出 Output】
- 产物：飞书卡片 / docx / HTML / JSON / 日志
- 推送：飞书群 oc_9ee530...（投资类免审直推）/ 静默（维护类）
- 格式锚点：引用 templates/ 下对应模板

【失败保护 Fail-safe】
- 硬失败(HARD_KILL/REFUSAL/TIMEOUT)：如何判定 + 是否告警
- 静默条件：何种情况不推送（全绿 SILENT）
- 阻断传播：异常是否阻断下游自动化

【有效期 Validity】
- 起：validFrom=YYYY-MM-DD
- 止：validUntil=YYYY-MM-DD（长期任务也设年度复审点）
- 复审：每月巡检未触发/僵尸自动化，到期清理
```

---

## 二、设计原则（来自文章模块4）

1. **先画流程图，再写代码**：触发→输入→输出→失败保护→有效期，每节点单独跑通再串。
2. **不要一上来搭长链**：坏了不知道从哪查。条件触发链路（异常→报告→高风险才推送）优于无条件全推。
3. **设有效期与失败保护**：自动化最怕悄悄跑偏——任务还在跑，结果已无意义甚至一直发错内容。
4. **条件触发优于定时全量**：监控发现异常才生成报告，有高风险项才推群，无则入库留档。
