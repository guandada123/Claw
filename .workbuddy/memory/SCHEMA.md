# SCHEMA.md — 行为规律与协作心智模型（L5）

> 跨会话沉淀的「用户怎么想 / 我们怎么协作」认知框架。非事实，是规律。
> 来源：07-11~07-29 多轮协作抽象。违反规律前先想是否该升级为铁律。

---

## 一、用户决策风格
- **先 Ask → 确认 → Craft**：不确定必问（如「仅创业板还是全放开」）；>2步任务先给 Plan；明确指令直接做。
- **技术自信，给结论不要教操作**：用户能自己配环境/读代码，要的是「结论+依据+风险」，不是 step-by-step 教程。
- **确认式推进**：删除/强推/force 类操作必「先确认再执行」（铁律已固化）；但纯内部修复（语法/import）可直接 Craft。
- **方案对比偏好**：给 2~3 个选项 + 各自后果，让用户拍板（如 A/B 方案表），而非替他决断。

## 二、技术债优先级模型
```
阻断型(功能坏/数据错) > 噪声明(误报/重复推送) > 体验型(慢/丑) > 整洁型(死代码/命名)
```
- 真实失败（如 CI ERESOLVE）必修；环境型 false-failure（缺 TOKEN/版本漂移）标注不阻断。
- 双副本/死引用属噪声明，审计澄清即可，不急着删（防回退优先于干净）。

## 三、记忆与资产化纪律
- **高价值成果资产化**：可复用工作流→skill；跨会话框架→MEMORY/SCHEMA；一次性→日志。
- **防回退 > 整洁**：锁定的脚本/配置改动须显式确认；DO NOT REVERT 注释标记经实测的正确解。
- **数据隔离**：投顾/助理/美股三系统数据不混；data/ 字段改动先确认；总本金授权值不可推翻。

## 四、推送与渠道规范
- **少即是多**：投资类直推飞书群；维护类默认静默，仅 ⚠️/🔴 异常推。
- **卡片化**：interactive 卡片，禁 --text 降级；验证改脚本先 --dry-run。
- **排程铁律**：单 RRULE 单 BYHOUR，多时段拆多条（静默丢槽无日志）。

## 五、外部仓库协作模式
- **Claw 是主场，StockInsight/QTS/Marvis 是外延**：本地修复→push→ Dependabot 合并。
- **分支策略**：fix 类直接 commit+push；divergent 历史先 fetch 对比，remote 更全则 reset 接受，缺失部分 cherry-pick 补回（不盲目 force）。
- **CI 信任度**：本地测试绿 ≠ 可合；环境型 CI 失败（ruff 漂移/gitleaks 缺 TOKEN）不阻塞合并判定。

## 六、错误响应模式
- 用户说「查一下」→ 实测验证假设，不空答；说「全做」→ 把列出的可选项全执行；说「确认删除」→ 先备份再删。
- 发现更优解（如 remote 已有更全修复）→ 主动对比，推荐接受更优而非硬推自己的。
