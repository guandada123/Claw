### ⭐ 教训
1. 🔴 **Docker 改资源前先看状态栏！**"Preparing to install update..." 时改资源=叠加 VM 重置。铁律：先点 Update 装完，再改 Memory。
2. 🔴 **docker volume ls 的时序陷阱**：容器没启动时 named volume 不显示，导致我误判"数据全部丢失"——应以实际启动后的 `\dt` 查询为权威信号。
3. 🟡 **多栈 compose up 前先做端口冲突检查**：macOS ControlCenter(5000)、SSH 隧道(8765) 两个系统级端口在 compose 里硬编码了，应建一个 `lsof -iTCP:<port>` 的 preflight 脚本。
4. 💭 **lockfile 不是 build 的银弹**：Docker 里 `npm ci` 用的 lockfile 来自 repo，如果 lockfile 是旧 node/旧环境生成的，依赖解析可能漂移→ build 中断。stockinsight 的 vite 8.1.3 就是典型。
5. 💭 **containerd 拉镜像失败别立刻 prune**：I/O error 时 prune 会死锁 13 分钟，阻塞所有 docker 命令。应该直接重启 Docker Desktop。
