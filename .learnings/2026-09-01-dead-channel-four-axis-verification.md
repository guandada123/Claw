# 判定「告警项是否为废弃死通道」的四维实锤法

## 背景
统一巡检中枢的「微信公众号通道 / wechat-download-api 登录过期」告警自 2026-08-17 起
累计 detect 200+ 次、飞书推送十余次，历次报告均只写「建议摘白名单 / 需人工扫码」，
**连续 38 次无实锤**，用户始终未处置 —— 因为建议缺乏可判定的证据，无法决策。

2026-09-01 用四维核查一次性定性：**0 活调用方的废弃死通道**。

## 四维实锤法（顺序执行，缺一不可）

| 轴 | 核查动作 | 判废标准 |
|---|---|---|
| ① 调度层 | `grep -rl "<脚本名>" ~/.workbuddy/automations` | 无任何自动化在调度 |
| ② 代码层 | `stat -f %Sm` 看引用该端点的所有文件 mtime | 长时间停滞（本案 15 天，且 5 个文件同批次） |
| ③ 产物层 | `find output -newermt "<7天前>"` + 产物目录 `ls -lt` | 产物断流（本案 19 天零新产物） |
| ④ 主链路独立性 | 找同业务的替代产出目录，看是否仍在正常产出 | 主链路每日有产出 → 死通道不影响业务 |

四维全中 = 死通道；任一维不成立 = 仍有活调用方，**不得摘除**。

## 关键结果
- 4 个脚本 + 1 个 collector 模块引用 `localhost:5001`，但 **0 个被自动化调度**
- `sync_wx_articles.py` 默认走 `cloud`（付费云 RSS），`local` 仅为可选分支 → 即便代码存在也不走 5001
- `output/wx_articles/` 最新 08-13（停 19 天）；而 `output/wx_reports/` 08-25~08-31 **每天连续产出**
  → 公众号内容链路整体是活的，仅本地 5001 轨死掉

## ★升级候选

### 1. 「建议」必须带可判定证据，否则等于没说（★）
重复 38 次的无证据建议是纯噪音。给用户的任何处置建议，必须附带能让用户
**一句话拍板**的判据（本案：0 调度 + 19 天断流 + 主链路独立 = 可直接摘）。
判据不全时，先补齐判据再提。

### 2. 判「通道/服务是否废弃」要查调度层，不能只查代码层（★）
代码里存在调用（`LOCAL_API = "http://localhost:5001"`）**不代表有活调用方** ——
可能是历史遗留分支、可选分支、或已被自动化摘掉调度。
**唯一可信判据是「有没有东西在定时跑它」**：grep automations 目录 + 产物 mtime。

### 3. 摘除监控项代价不对称，不得自动化擅自执行
摘白名单 = 永久失去观测，不可逆性高于文件清理。即便四维全中，也**只给结论不擅自改**，
等用户一句话确认。与「误判 P0 代价不对称」同理：推翻一个判断便宜，错误摘除贵。

## 复用命令
```bash
# ① 调度层
grep -rl "script_name" ~/.workbuddy/automations
# ② 代码层
grep -rn "endpoint" <proj> --include="*.py" --include="*.sh" -l | xargs stat -f '%Sm %N'
# ③ 产物层
ls -lt <output_dir>/ | head -5
# ④ 主链路
find <proj>/output -newermt "7 days ago" -type f | head
```
