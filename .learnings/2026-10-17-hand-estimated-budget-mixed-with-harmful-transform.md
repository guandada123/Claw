# ★升级候选 —— 手工估算的「可压缩预算」里混着**已知有害项**：0B 被估成 76B；同一批手工值还把「物理够用」判反

**日期**：2026-10-17（每日记忆维护 1a-2 复核时发现）
**等级**：P2（**无直接损害**；但会让下一轮去做一次「零收益 + 有毁文件风险」的改写，且使结论建立在错论据上）
**类型**：取证口径（手工值无机器核对 · 变换集合未自证无害）／ estimation-caliber
**状态**：已机器化（`memory_headroom_check.py` 输出「最长规则 + 物理口径」）+ 已更正 skill Step 0.31 的 264B

---

## 1. 现象

10-16 那轮给用户级副本 B 做完排印归一后，余量从 **0B → 238B**，并宣布「授权手段已用尽」。
这个结论靠**两个当场手算的数**支撑：

1. 「物理约束是最长单条规则长度（实测 **264B**）」
2. 「还可压 ≈238B / 剩余零语义空间不多」

10-17 把同一件事交给脚本后，两个数**都被推翻**：

| 手工值 | 机器实测 | 后果 |
|---|---|---|
| B 最长规则 264B | **261B** | 量偏 3B |
| 「B 只是**阈值**口径问题，物理上够用」 | B 余量 238B **<** 261B | **判反了** —— 物理上也装不下自己最长的那条规则 |
| （从未量过）项目级最长规则 | **576B**（余量 801B） | 首次被看到，离越线只差 225B |

## 2. 第二个坑：估算用的变换集合本身没自证无害

估算「剩余可压缩空间」时，我把「全/半角标点相邻空白归一」的相邻集合写成
`[,;:()\[\]≠=+‑/<>]` —— **里面带着 `-`**，正是 10-16 吃掉 76 个 bullet 空格的那个元凶。

- 带 `-`：估出 **76B** 可省
- 去掉 `-`：同一变换收益 **0B**

⇒ 那 76B **全部由"不该做的那个变换"贡献**。若不复核，下一轮会照 76B 去做一次既无收益又有风险的改写。

## 3. 根因

「结论的论据」和「结论」被同等对待了，但**论据是现算现用的自由文本**，没有任何机制回读它。
同族于已固化铁律「会腐烂的声明值必须由脚本回写，禁手算」（10-09，第 5 次复发）——
只是这次手算的不是文件里的声明，而是**报告里的论据**。两者都是"同一事实的第二份自由副本"。

## 4. 处置

1. **机器化物理口径**：`check_memory_visibility._layout` 新增 `info['longest_rule']`，
   **复用与 `rules` 相同的切片和 `startswith('- ')` 谓词**（不引入第二个口径）；
   `memory_headroom_check.py` 输出「最长规则 NB | 物理口径 ✅/⚠️」，**只作信息、不参与 rc**
   （一个判据只答一件事：够不够**大** = 阈值；够不够**用** = 物理口径）。
2. **更正 skill** Step 0.31 里写死的 264B，并注明「物理够用」已被证伪。
3. **纪律**：估算「还能压多少」之前，先逐个元素自证**变换集合无害**（问「它上次有没有闯祸」）。
   **收益为 0 也是结论**，而且比"有 76B"更有价值 —— 它把「授权已用尽」从主张变成证据。
4. 顺带：本地 `ruff check` 通过 ≠ pre-commit 通过（**`ruff format` 是另一个钩子**，
   本轮实测导致首次 commit 失败并自动改写文件）。

## 5. 未闭环

B 余量 **238B**（< 阈值 500B，且 < 自身最长规则 261B）。零语义压缩预算已被机器证明 = **0B**。
处置三选一（阈值改物理口径 / 授权措辞压缩 / 授权规则合并并接受证据重编号）—— **待用户拍板**。
