# ★升级候选：新建自动化的「飞行前检查」—— prompt 里的每条 Bash 命令必须逐字实跑

**日期**：2026-10-09（对 04:00 索引自动化做飞检时）
**等级**：P1（一条 prompt 里抓到 **4 个缺陷**，其中 3 个会让任务**静默失败或静默误报**）
**类型**：best_practice（可复用 SOP）
**状态**：已修复并复验通过

---

## 1. 起因

新建的「🗂️ 记忆索引重建 + 新鲜度自检」（每日 04:00）**首次运行前**做了一次飞检：
把 prompt 里所有 `Bash:` 行原样抽出来、在**真实执行环境**（cwds + `automation_preamble.sh`）里逐条跑一遍。

**结果：一条 prompt 里 4 个缺陷，全部当场拦下。**

| # | 缺陷 | 若未拦下的后果 | 为何"看起来没事" |
|---|---|---|---|
| 1 | **时区错位**：判据把库内 `MAX(updated_at)`（**UTC**）与 `date.today()`（**本地**）比日期 | 该任务跑在 **04:00 本地 = 前一天 20:00 UTC** → **每天必然误报"索引未刷新"** | 白天手动测试时本地日期与 UTC 日期**相同**，测试通过 |
| 2 | **路径错**：`build_memory_index.py` 在 `$HOME/.workbuddy/scripts/`（全局），却写成 `$SCRIPTS/`（Claw 目录） | `can't open file ... No such file or directory` | **`cmd \| tail` 把退出码换成了 `tail` 的 0** → 外面看是"成功" |
| 3 | **参数枚举错**：`push_card.py --level` 只接受 `alert/warning/info/success`，却写成 `--level warn` | argparse 直接报错 → **偏偏在需要告警的失败路径上推不出去** | 只在异常分支触发，正常路径永远测不到 |
| 4 | **管道吞退出码**（与 #2 同源）：判据/重建命令若带管道，`$?` 反映的是管道末端 | "什么都没重建"看起来像成功 | 输出文本正常 |

**共 4 个，其中 #1 #3 是每天都犯的错，#2 #4 是"静默成功"。**

## 2. 为何必须"逐字实跑"而不是"读一遍"

四个缺陷有共同特征：**它们在白天、在交互式 shell 里、在"看起来对"的情况下都不会暴露。**

- #1 只在**跨 UTC 零点**的时段暴露；
- #2 #4 只在**退出码**上暴露，而退出码被管道吃掉了；
- #3 只在**异常分支**暴露。

→ **"我读了一遍觉得没问题"完全无法覆盖这四类。唯一能覆盖的是"在真实环境逐条执行并读回退出码与输出"。**

## 3. 可复用 SOP（建议纳入所有新建/大改自动化的交付流程）

```
① 抽命令  从 prompt 里正则抽出所有 `Bash:` 行
② 建环境  cd <该自动化的 cwds> && source <其 preamble>
③ 逐条跑  跳过含 {占位符} 的行（由 LLM 运行时填充），其余**原样执行**
④ 读两样  退出码 + 关键输出行（不能只看输出文本！）
⑤ 反向验  把能调坏的参数调坏（如阈值设 0），确认它能**报出**问题 —— 防"检查恒绿"
⑥ 回读    改完 prompt 后，从 DB 里**重新读出** prompt 再跑一遍 ①–④
          （防"我改的是草稿，库里存的是旧版"）
```

**第 ⑤ 步不可省**：一个从不报错的检查，与没有检查等价。
**第 ⑥ 步不可省**：prompt 是通过工具写进 DB 的，必须回读确认落库内容才是被执行的版本。

## 4. 与既有铁律的关系

- 「🔴 验证 `trap EXIT` 清理必须另起一个 shell 调用」「🔴 手动跑通过 ≠ 定时环境通过」**同族**：
  都指向**"验证必须换到目标上下文"**。本条把该原则**前置到交付流程**里（不是出事后补验）。
- 「🔴 静态快照类数据源必须有『刷新脚本+过期告警+备份』三件套」的**补强**：
  三件套齐了还不够，**"刷新脚本"本身必须能被正确调用**（#2 就是"脚本存在但路径写错"）。
- 「框架级『成功』≠ 真实产出」**同族**：#2 #4 正是"退出码/输出看起来成功，实际什么都没做"。

## 5. 附带产出

- 判据脚本从 prompt 内嵌 heredoc **搬进独立脚本**（`memory_index_selfcheck.py`），
  并归位到与其余 4 个记忆脚本同一目录（`~/.workbuddy/scripts/`，单一位置纪律）。
  理由：改判据不必再整段重发 prompt（转录风险），且可单测。
- 4 个坑全部写进该 prompt 的「铁律 ④」小节，标注"勿重犯"。
- 判定口径从"日期相等"改为"**年龄 ≤ 2h**"—— 边界不敏感，换时区、跨零点都不再出问题。
