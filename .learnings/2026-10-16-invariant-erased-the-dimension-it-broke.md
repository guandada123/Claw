# ★升级候选 —— 「不变式」擦掉了被改动的那个维度：一条批量排印改写吃掉 76 个 bullet，而内容不变式全程绿灯

**日期**：2026-10-16（记忆维护自动化 automation-1780769419635，03:30）
**等级**：P1（**盲区 + 破坏性**：一次本应"零语义"的批量改写把全部规则行的 bullet 语法改坏，
而写前自检的不变式**恰好擦除了被破坏的那个维度**，一路放行；更坏的是下游 `--fix` 把解析出的
`0 条` **写进了文件**）
**类型**：blind-spot / invariant-erased-the-dimension-it-broke　+　destructive-fixer writes parser failure
**状态**：已修复（从备份逐字节还原后重做），并给写盘型修复器装上合理性闸门 + 证伪实验。

---

## 1. 现象

B（`~/.workbuddy/user-24688a34-…-personal/MEMORY.md`，**实际被注入**的用户级记忆）规则层
恰好填满可见区（余量 **0B**）。按 `registry.pending_actions` 的 **PA-007**
（`owner=auto`、机器触发条件「任一 MEMORY.md 余量 <500B → 触发一次**精简**，不动语义」）执行精简。

为此写了一次**只做同字异宽标点归一**的批量改写（`，；：（）`→`,;:()` + 相邻空白收敛）。
首版把"允许删空白"的邻接字符集开成宽集合，**含 `-`**。于是 `(?<=-)\s+` 把
**每一行规则开头的 bullet 空格**也删了：

```
- 🔴 搜到 ≠ 验完：否决现成方案的理由必须是「查过的」，且必须留复查点
-🔴 搜到 ≠ 验完:否决现成方案的理由必须是「查过的」,且必须留复查点
```

`check_memory_visibility._layout` 判定规则行用的是 `l.startswith('- ')` → **数出 `rules=0`**。

## 2. 为什么写前自检没拦住（核心教训）

我装的写前自检里有一条"内容不变式"：

```python
key = lambda s: re.sub(r'[\s，,；;：:（）()]', '', s)     # 擦掉空白 + 六个标点
assert key(after) == key(before)                          # 逐行必须相等
```

它**全部通过**。原因不是它写错了，而是它的**擦除集合恰好包含被破坏的那个维度**：
`\s` 被擦掉 ⇒ `- 🔴` 与 `-🔴` 的 `key` 完全相同 ⇒ **对 bullet 被吃掉完全失明**。

> **判据（可迁移）**：**不变式必须窄于变换，不能等于变换的擦除集合。**
> 只证明"值没变"是不够的——**格式本身承载语法**（markdown bullet、`## `、`**── 证据 N ──**`、
> 行首缩进、代码围栏），而这些恰恰活在"空白/标点"这些被当作"无意义"而擦掉的维度里。
> 因此**每一类"值不变"断言，都必须配一条"结构角色"断言**：
> 行首 bullet 仍为 `- ` 且条数守恒 / `## ` 标题数守恒 / 证据块标记数守恒 / 行数守恒 / 作用域外零改动。

## 3. 下游把它固化了（比"没拦住"更坏）

`check_memory_visibility.py --fix` 读到 `rules=0` 后**照单回写**，文件里出现：

```
**本文件**:注入上限 · 规则层 0 条各一行(止于 **7,913B**)· 铁律证据库 · 截断点
## 🔴 铁律(规则层 · 0 条一览 · 证据正文见文末「铁律证据库」)
```

它"算出来了所以写下去"。**后果比不修更坏**：声明从「正确」变成「错误」，
而写入成功 ⇒ readback 全绿 ⇒ **没有任何红灯**。

> **判据（所有会写盘的修复器）**：写盘前必须过**合理性闸门**，问的是
> 「这个实测值**物理上说得通吗**」，而不是「我算出来了吗」。
> 且闸门**不能只判 `== 0`**：本次破坏后仍有 **6 条** `- ` 幸存 ⇒ 只判 0 会放行非 0 的错值。
> 正确做法是**两个独立口径必须一致**：
> 严格 `l.startswith('- ')` vs 宽松 `r'-\s*\S'`；不一致 ⇒ 文件语法已坏 ⇒ **拒绝写盘**。
> 同理对偏移量加 `0 < off <= bytes` 的范围闸门。

## 4. 第三个坑：证伪实验自己的断言读错元组位置

装上闸门后我写了证伪实验（合成"bullet 部分被吃 / 全被吃"，期望"拒绝且文件零改动"），
断言写成 `'拒绝回写' in ch[0][0]` —— 但 `ch[0][0]` 是**路径**，消息在 `ch[0][1]`
⇒ **闸门明明生效却被判为失败**。同族铁律：**检查器必须自证「它在读它该读的那一格」**。

## 5. 处置与验证（全部机器可查）

- 从备份 `.bak-20261016-033000` **逐字节还原**（把 `--fix` 写入的 `0 条` 一并消除）；
- 改用**只归一化同字异宽标点**（`、。「」` 属不同字形，**不换**）+ **显式保护行首 2 字节**，
  并对 `- 🔴` 之外的行首 bullet 一并保护；
- 写前自检 6 条全过：内容不变式（逐段、跳过代码段）+ 规则 76 且均 `- ` 开头 + `## ` 数守恒 +
  证据标记守恒 + 作用域外零改动 + 行数守恒；
- 结果：改动 **56 行**（全部落在第 3–83 行＝索引头+规则层），文件 **100,428 → 100,190B**，
  规则/证据 **76/76 守恒**，反引号 1180/1180、`**` 1023/1023、行首 `- ` 206/206 逐项不变（无残片）；
- `--fix` 回写后 `rc=0` 且**幂等**（复跑"无声明需要回写"）；覆盖率审计三份 **0 未覆盖**；
- 闸门证伪实验三例：**部分被吃 → 拒绝+零改动** ✅ ｜ **全被吃 → 拒绝+零改动** ✅ ｜ 正常文件 → 照常回写且幂等 ✅。

## 6. 顺带：一条"已定策"是怎么变成死信的

PA-007 早在 2026-10-10 就把这件事定为 `owner=auto` 的**机器触发策略**，
判据写着「余量 <500B ⇒ 触发一次精简（不动语义）」。
B 的余量 **0B** ⇒ 触发条件**早已满足**，而 10-14 / 10-15 / 10-16 连续三轮
都把它当作「挂起待用户决定」上报。**策略有触发器、触发器已点火，但没人把它接到执行上** ——
与"锁只 check 不 done = 死守卫"同族。

## 7. 顺带发现（未闭环，需用户决定）

按"不动语义"的授权口径，**可腾出的上限就是 238B**（措辞压缩有 10-05 掉子句前科、规则合并会连带
重编号全部证据块＝永久性可用性损失，两者均被 PA-007 明确否决）⇒ **授权手段已用尽，够不到 500B**。
而守卫阈值 **500B** 与自己技能里 Step 0.20 的**验收线 300B 自相矛盾**，
且 500B 的理由「再加铁律就会挤出可见区」**在 500B 处并不成立**——
**物理约束是最长单条规则长度**（实测 **264B**）。⇒ 属**恒真红灯**，需改阈值口径或授权更强的压缩。
