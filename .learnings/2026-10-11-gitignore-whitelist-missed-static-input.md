# ★升级候选：`.gitignore` 白名单漏掉**静态权威输入** → CI/新克隆静默降级

**日期**：2026-10-11（处置触发器首次提交触发 CI 红）
**等级**：P1（不是测试问题：**生产逻辑在 CI / 任何新环境里静默降级**）
**类型**：environment-drift / silent-fallback
**状态**：已修复（日历入库 + 用例与外部文件解耦 + 临时移走文件验证 927 passed）

---

## 1. 现象

新写的 `tests/test_check_disposal_triggers.py::test_main_retires_when_target_met`：
**本地全绿、CI 红**（`assert 1 == 0`）。同一提交的其余 5 个 job 全绿。

## 2. 根因（不在测试里）

```
① .gitignore: `.workbuddy/data/*` + 白名单只列了
   automation_health / macro_data / stock_pool / simulation / sector_cache
   → **astock_holidays.json 从未入库**（它看起来"在仓库里"，其实只存在于本机磁盘）
② CI/新克隆里 `is_trading_day.load_holidays()` 找不到文件 → `sys.exit(2)`
   → 调用方（守卫/触发器/门禁脚本）捕获后统一**降级为「自然日」**
③ 我的触发器于是把「10 天前」算成 ≥5 个交易日 → T3 误触发 → 断言失败
```

**关键点：测试红只是"最先被看见的症状"**。真实影响面更大：
- `is_trading_day.py` 命令行门禁：节假日会被判成交易日 → 盘后自动化在假期照跑；
- 任何新部署/新克隆拿到的都是"没有日历"的系统（且只留一行 stderr）。

## 3. 判据

1. **"文件在本地存在" ≠ "在仓库里存在"**。凡是被 `.gitignore` 用通配符挡住的目录，
   都要定期核对「静态权威输入」是否在白名单里（本例：日历、代码→板块映射、股票池）。
   自查一行：`git ls-files .workbuddy/data/` 与 `ls .workbuddy/data/` 做差集。
2. **降级要能冒烟**：本例的降级只写 stderr，业务照跑。既有的 `cal_ok` 标注是对的，
   但没有任何"日历不可用"的**告警**——建议巡检增加一项（本地/CI 双环境校验）。
3. **测试与外部文件解耦**：跨环境的用例必须把「环境状态」显式注入
   （本例新增 `_fixed_calendar()`），否则同一个用例在不同环境给出不同结论。
4. **验证方式**：把文件**临时移走**再跑全量测试（而不是只看"本地能过"）。

## 4. 同族

- 「本地全绿 ≠ CI 会绿」（已知）→ 本例给出了新的具体成因：**输入文件没入库**
- 「降级必须留证」：静默降级 = 把"缺输入"伪装成"正常工作"
- 「判据被复用，盲区成对出现」：同一个日历缺文件，测试与生产**一起**降级
