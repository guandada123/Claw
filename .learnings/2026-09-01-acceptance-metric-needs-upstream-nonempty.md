# 验收指标的前提：目标表 0 行不等于故障，先查上游有没有数据

> 日期：2026-09-01 | 场景：统一巡检中枢 run#56 | 等级：P1（结论修正）
> 关联：run#55 的 pmf 调度作业修复验收

## 发生了什么

run#55 定位并修复了 pmf 3 个调度作业被 `runInBackground()` 静默杀死的问题，
当时的**故障证据之一**是「目标表 `metric_snapshots`/`metrics`/`risks` 全 0 行」。

run#56 复查：作业确实恢复执行（日志 mtime 每 30min 精确跳动，修复前停在
08-09 / 08-28 / 08-30），**但目标表依然全 0 行**。

深挖后发现：

```
projects       = 0
users          = 0
integrations   = 0
metric_snapshots / metrics / risks = 0
slow_queries   = 1037 条，但时间范围 2026-06-24 ~ 2026-07-08，近 7 天 0 条
```

pmf **从来没录入过任何业务数据**，最后真实活动是 07-08。因此日志里
「总数 0 / 已采集 0 / 错误 0」是**符合预期的空转**，不是管道故障。

## 根因

我把「下游表 0 行」当成了故障证据，但没验证**该指标作为故障信号的前提**：
上游（`projects`）必须有数据，下游才可能产生数据。

上游为空时，下游 0 行是**恒真命题**，对「管道是否健康」零信息量 ——
它既不能证明管道坏了，也不能证明管道好了。

## 教训

### ✅已升级(2026-09-06) 1：验收指标必须先校验「前提成立」

用某个量做验收/告警指标前，先问一句：
**「这个量为 0（或为异常值），有没有可能只是因为上游为空/未配置？」**

- 表行数 → 先查上游实体表是否非空
- 采集计数 → 先查采集源是否配置了
- 错误率 → 先查请求量是否非零（0/0 ≠ 0%）

具体到本案：判「指标采集作业是否正常」应改为
`projects > 0 AND metrics >= 0`，或干脆用「作业是否执行过」+「有无异常」两段式。

### ✅已升级(2026-09-06) 2：日志心跳正常 ≠ 有效产出

run#55 我用**日志 mtime** 验收作业恢复，得到的是**假阳性** ——
心跳证明「作业跑了」，不证明「作业干成了」。

心跳 → 执行；产出 → 有效。两者之间还隔着「数据源」「配置」「权限」三道关。
验收要落到**产出物**（DB 行数 / 文件 / 下游副作用），但用产出验收时又回到候选 1 的前提问题。

正确顺序：**先确认上游有数据 → 再用产出验收 → 心跳只用于判死活**。

### ✅已升级(2026-09-06) 3：日志里的「成功」措辞会掩盖「什么都没做」

```
✅ 全部指标采集完成
| 总数   | 0  |
| 已采集 | 0  |
| 错误   | 0  |
```

打勾 + 零错误 + 零采集 —— 三个信号里两个「好」，整体读起来像成功。
**「0 错误」只在有工作量时才有意义**。

建议：作业日志应把「处理总数=0」单独标为 `⚠️ 无数据源` 而非混入成功态。

### ✅已升级(2026-09-06) 4：跨环境对照是定位「配置缺失」最快的手段

同一台机器上：
- `project-monitor-fusion-scheduler-1` → `date` = **CST 17:45**
- `quant-strategy` → `date` = **UTC 09:45**

一对比立刻知道：**时区不是镜像限制，是漏配**。
直接把一个「需要重建镜像」的重量级待办，降级成「加一行环境变量」。

遇到「某环境不具备某能力」时，先找**已经具备该能力的同类环境**做对照，
能瞬间区分「做不到」和「忘了做」。

### ✅已升级(2026-09-06) 5：沉默型缺陷 —— 不报错、不告警、只在特定时间窗犯错

（本轮顺带发现的 QTS 时区问题，见 `QuantTradingSystem/.learnings/`）

容器 UTC + 代码零时区保护 → `datetime.now()` 比北京时间早 8 小时。
它**从不抛异常、健康检查全绿、日志时间戳看起来也自洽**，
只在每日北京 00:00–08:00 这个窗口把日期字段写错成前一天。

这类缺陷所有「异常驱动」的监控都抓不到 —— 没有异常可抓。
只能靠**主动的语义校验**（时间戳量级是否合理、日期是否应是今天）来发现。

## 复用检查清单

判定「某个作业/管道坏了」之前，按顺序确认：

1. 上游数据源非空？（实体表 / 配置表 / 采集源）
2. 作业确实执行了？（心跳 mtime / 执行计数）
3. 执行时有无异常？（错误日志 / 退出码）
4. 产出物符合预期？（DB 行数 / 文件 / 下游副作用）
5. 若产出为 0，回到第 1 步 —— 大概率是上游空，不是管道坏
