## 1. 怎么发现的

今日发现池冒出 3 条候选。**不猜、直接拿落地闸门逐条预检**（直接调 `quality_gate`，无副作用）：

```
disc-20261012-01  [host]          承载方缺失(空)
disc-20261012-02  [risk]          risk=medium 高于阈（✓ 正确拦下）
disc-20261012-03  [check_cmd_bad] check_cmd 引用了不存在的路径
```

## 2. 缺陷①：`check_cmd_bad` 假设「目标文件已存在」→ 整类误杀

两条候选（01/03）的 `doc_target` **正是** check_cmd 里 `test -f` 的那个文件——
**提案就是要新建它**，它当然还不存在 → 闸门判"引用了不存在的路径 → 指标永远无法证真" ✗。

**这不是脏数据，是判据缺一类状态**（"待创建"）。它把「新建文档」这一整类候选全部挡在门外，
而表面上只是"个别候选质量差"。

修法：**token 以本候选 `doc_target` 结尾时跳过该检查** —— 那是它自己要创建的文件。
并补**反向对照**用例（**别人的**不存在路径仍须判 bad），证明没把检查放宽成空检查。

> 判据设计通则：**给"不存在的路径"判死之前，先问「这个不存在的路径是不是本提案要创建的」**。
> 同族：`check_disk` 的"路径不存在 → 报磁盘正常"（该报没报），本条是"不该报的报了"。

## 3. 缺陷②：两道闸门口径不一致，且松的那道**没人调用**

| | 位置 | 判据 |
|---|---|---|
| 登记端 | `discovery_schema.validate_candidate()` | **「有 skill 或 有真实项目锚点」** → 合法 |
| 落地端 | `apply_doc_candidates.quality_gate(require_host)` | **必须**有 skill 且目录存在 → 弹掉 |

于是"只有项目锚点、没有 skill"的候选 **登记时合法、落地时必死** ✗。
更糟的是：`validate_candidate` **只在一次性迁移脚本里被调用过** ——
运行时登记路径**根本不调它** → 它是一道**没接线的校验**（同族：实现了但没人调）。

> 「校验/占位符/安全检测必须下沉到被复用的内层函数」的反面：
> **校验函数存在 ≠ 校验在跑**。判断时要 grep 调用方，不只看函数在不在。
