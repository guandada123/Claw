# 2026-10-12 · 让测试"真跑"，是发现率最高的一个开关 ★升级候选

## 现象
QTS 的契约/性能/E2E 测试长期 **21 个 failed**，全是 HTTP 401 —— 服务端加了鉴权、测试没带凭据。
看起来是"测试过时"，所以很诱人**直接改成 skip**。但那样做，等于**关掉这道防线**：
这些用例防的正是 **API 契约漂移**，而 Claw 的 `qts_client` 直接依赖该 API。

## 处置（关键在"真跑"而不是"消红"）
不是把 red 变 green，而是**把测试恢复到真校验状态**：
- 凭据显式配置优先（`QTS_JWT` / `QTS_API_KEY`）；
- 都没有 → **自签 dev 令牌**（纯标准库 HS256；服务端在非 dev 会拒绝以 dev 默认密钥启动，
  故该令牌**只可能在 dev 生效**，不是生产后门）；
- **401 分两态**：自动令牌被拒 → skip（环境所限，附原因）；**显式凭据仍 401 → 判失败**。

## 结果：真跑的当天就连着撞出真问题
① `/api/v1/positions` 500（`account_id` 列不存在）；② 修好后又撞出 `/orders/summary/daily` 500
（`profit_loss` 列不存在）；③ 顺着做全量对账，发现**整片 schema 缺口**（5 表 10 列 + 1 缺表）。
**这些缺陷此前躺了不知多久** —— 被 401 与 skip 双重掩盖。

## 判据
1. **"红"先分类**：是"用例过期"还是"被测对象坏了"？**宁可先让它真跑再判断**，
   不要用 skip/放宽断言把红抹平 —— 那会把真缺陷一起埋掉。
2. **skip 必须带原因**，且**不得替代"真校验"**；能自给的凭据就自给（本地/dev 优先）。
3. **改测试的边界**：只动测试侧（凭据、路径、断言），**不为了让测试变绿而改服务端策略** ——
   本次坚持不动实盘 API 的鉴权。
