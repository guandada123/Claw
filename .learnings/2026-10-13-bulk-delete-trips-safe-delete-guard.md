# ★升级候选 —— 新加的「缓存清扫」一次删 1861 个文件，撞上 safe-delete 护栏把整条评估链打断

**日期**：2026-10-13（Alpha101 因子评估自动化 automation-1786666500469）
**等级**：P1（当日自动化直接失败、无报告产出；护栏本身工作正常，是**新代码没适配护栏**）
**类型**：engineering_practice / guard-interaction（批量删除撞本仓护栏）
**状态**：本次已绕过（存量已由自然运行消化）；**建议改代码**——清扫必须分片。

---

## 1. 现象

17:10 的例行评估 **5 秒**即退出，退出码 1，stdout 只有一行、无任何业务输出：

```
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":50,"threshold":50,
 "scope":"turn","targets":[".../data/alpha/bars_300724.csv"],"targetCount":1}
```

同日新增的 `alpha_data.sweep_cache()`（10-13 TTL 补丁的一部分）会把
mtime 超 14 天的 `bars_*.csv` 全部 `unlink()`。而存量缓存**全部**停在 08-13/14
（见 `2026-10-13-alpha-cache-no-ttl-froze-two-months.md`），
即**一次要删 1861 个文件** → 超护栏阈值（一次 >50 个）→ 整条评估中断。

## 2. 取证

| 检查项 | 结果 |
|---|---|
| 护栏语义（本仓自述） | `check_tracked_tree.py:24` ——「本仓 safe-delete 护栏会拦『一次删 >50 个文件』」；`memory/2026-10-05.md:98` 已记「一次 665 个文件 → bulk delete 拒绝」 |
| 触发点 | `alpha_data.py:243-250` 循环 `CACHE_DIR.glob("bars_*.csv")` → `p.unlink()`；由 `load_universe()` 经 `_sweep_cache_once()` 触发 |
| 删除量 | 待删 1861 个（全部 Aug 13/14） |
| 是否致命 | 是：`sweep_cache` 是**同步前置步骤**，`load_universe` 在它之后，故评估连"股票池"那行都来不及打印 |
| 绕过验证 | 先清空存量后再跑：评估 **26s** 完成、退出码 0、报告正常 |

→ 说明护栏**没有误判**（确实在批量删），问题在**新代码没有按护栏约束设计**。

## 3. 根因

`try/except OSError: continue` 让单文件删除失败可被吞掉，但**护栏拦的是"单次调用内累计删除数"**：
第 51 个起整个进程被拒 → 既没有部分成功的可见日志，也没有"删了 N 个"的收尾输出。
表现为**静默中断**（退出码 1 + 一行护栏文案），排查成本高。

## 4. 教训（待周度升级为铁律）

1. 🔴 **本仓任何"批量删除"代码都必须分片**（每片 ≤ 护栏阈值的 1/2，即 ≤25 个/次），
   并在每片之间落一条可见日志。直接 `unlink()` 循环 = 迟早撞护栏。
   （同族既有铁律：`shutil.rmtree` 被拦，见 `check_tracked_tree.py` 自述。）
2. 🔴 **`except OSError: continue` 会让"护栏拦下"看起来像"删完了"**——
   清扫类函数必须返回/打印 `removed/n_failed`，否则 `removed_bars=0` 与 `removed_bars=1861` 无法区分。
   （本次 `sweep_cache` 其实**返回了** dict，但 `_sweep_cache_once()` 只在上层异常时打印，
   正常路径一个字都不输出 → 仍然不可观测。）
3. 🔴 **护栏阈值是环境约束的一部分，写新功能前先问"它会不会撞护栏"**：
   本仓已知约束至少有 ① 单次删 >50 个文件被拦 ② `rm -rf` 被拦 ③ tracked-tree 校验。
4. ⚠️ 关联：这条路线的"存量消化"设计（不手工删、靠自然运行）方向是对的，
   但**只有 TTL 生效后 mtime 才会更新**，所以**存量文件永远超 14 天** ——
   即"靠自然运行消化"在**第一次**必然触发全量删除。
   要么分片，要么在补丁上线时显式安排一次受控的分批清理。

## 5. 遗留

- 建议改动（未实施，等确认）：
  `sweep_cache()` 增加 `batch_size=25` 分片 + 每片日志 + 汇总行
  `[alpha_data] 缓存清扫: bars 删 N / 失败 M / eval 删 K / 释放 X MB`。
- 复核点：若本自动化停跑 >14 天，下一次运行会再次触发全量清扫 → 会**再次**静默失败。
  在分片补丁落地前，该风险常驻。
