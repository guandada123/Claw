# 告警文案滞后于实现：写着「告警零出口」，实际中枢已在兜底推送

**日期**：2026-09-02（统一巡检中枢 核查）
**等级**：P2（不影响功能，但把处置引向错误路径）
**状态**：已修复并验证
**✅已升级(2026-09-06)**：是（「改了判据就要改文案」是可固化为 checklist 的）

---

## 1. 现象

`check_cost_anomaly` 持续告警：

```
本月累计 ¥44.48 / 预算 ¥400，月底预估 ¥667；告警委托断链——
成本监控自动化 automation-1782002819199 当前状态 PAUSED，中枢原只做 note 可见性、
把超预算告警委托给它，该告警当前零出口。建议恢复该自动化或改由中枢告警
```

但取证 `.ops_alerted.json`：`成本监控@本月累计 ¥#.# / 预算 ¥#` 在 **1.3h 前刚推送过**。
告警**明明有出口**。

## 2. 根因：run#65 改了实现，没改文案

run#65 已经把「委托断链且超预算」升级为真实告警，即**中枢已接管兜底推送**。
但告警文案仍是 run#65 之前的旧措辞「该告警当前零出口。建议恢复该自动化或改由中枢告警」。

后果：处置者读文案会去「恢复成本监控自动化」——
而真正缺失的出口**已经由中枢补上**，恢复受托方只会造成双推 + 增加 LLM 成本。
**告警把人引向了一条无效路径。**

## 3. 修复

文案改为如实表述，并给出可执行动作：

```
本月累计 ¥44.48 / 预算 ¥400，月底预估 ¥667（超 ¥267）；成本监控自动化
automation-1782002819199 状态 PAUSED、委托链已断，本条由中枢兜底推送
（8月超支¥778.23全程无人告警即因该断链）。处置：执行 budget_guard 降级策略
```

并新增：未超预算时，委托断链状态写入 `note` 留痕——
避免「下次超预算时才第一次发现委托是断的」。

## 4. 验证

实测输出确认文案含：超预算金额 ¥267 / 受托方状态 PAUSED / 中枢兜底 / 可执行处置。

## 5. 通用教训

**改告警判据时，文案是判据的一部分，不是装饰品。**

告警的完整契约 = 「判据 + 结论 + 建议动作」。三者必须同批更新：
- 判据变了 → 结论可能变（「无出口」→「已兜底」）
- 结论变了 → 建议动作必然变（「去恢复」→「去降级」）

**固化为 checklist**：任何修改告警 `return` 分支的改动，
必须同时检查该分支文案里的三件事：①状态描述 ②因果归因 ③建议动作。

**附带教训**：把告警**委托**给另一条自动化时，委托关系是一个隐性依赖。
受托方被暂停（此处自 08-29 起，另一条成本看板日报同样 PAUSED）不会报错，
只会静默丢失整整一个告警维度——8 月超支 ¥778.23（超预算 95%）全程无人知晓即因此。
委托必须有存活校验，且校验失败要能自动收回。
