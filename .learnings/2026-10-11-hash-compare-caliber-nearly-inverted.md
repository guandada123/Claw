# ✅已升级(2026-10-11)→R73 —— 比对哈希**差点判反** —— 算法与粒度错一个，结论就反了（「在用凭据在公开仓」被判成"已轮换"）

**日期**：2026-10-11（PA-013 Wind MCP token 取证）
**等级**：P0 级风险 × 手动取证险些失手（结论错 = 把一个**公开仓里放着的有效凭据**判成"安全"）
**类型**：取证口径错误（readback 读错）
**状态**：已闭环（凭据已轮换）；已加 `--compare-env` 把口径固化

---

## 1. 差点得出什么错结论

任务：判断「git 历史里泄漏的 Wind token 是不是**还在用**的那把」。

- **我第一次的比法**：对 `.env` 里的**整值**算 `sha1(...)[:10]`，与扫描器输出的哈希前缀比 → **不同**
  → 结论：🟢「已被换过，安全」。
- **正确比法**：`scan_git_history_secrets.py` 用的是 **`sha256(match.group(0))[:10]`** ——
  **sha256**（不是 sha1）+ **正则匹配片段**（不是整值）。
  按同口径重算 → `.env` 的 `WIND_MCP_TOKEN` / `WIND_API_KEY` 命中 **`67c05351e1`**
  → 🔴 **公开仓历史里那把 = 现在正在用的那把**。

一个**算法**（sha1 vs sha256）+ 一个**粒度**（整值 vs 匹配片段）之差，
把"有效凭据暴露在公开仓"读成了"已经轮换过"。

## 2. 为什么这类错特别危险

- 它**不会报错**：两个哈希都是合法的十六进制串，比不相等就是"不同"。
- 它**给出的是安全结论**：错误方向恰好是"更让人安心"的那一边 —— 没人会去复核一个已经绿了的结论。
- 它**可复现地错**：只要还用手算，下次还会错。

> **读错的 readback 比不读更致命。**

## 3. 修法：把口径固化成工具，不靠人记

给扫描器加 **`--compare-env <env文件>`**：复用**同一份 `PATTERNS` 与 sha256[:10]**
去比对"当前在用的值"与"历史命中值"，给出 rc：`0` 不同 / `1` 命中 / `2` 读不到。

```bash
python3 .workbuddy/scripts/scan_git_history_secrets.py --compare-env .env
```

**刻意不跳过 allowlist**：若"在用值"命中一条「已轮换」豁免，那是**豁免写错了**（值其实没换），
必须报出来而不是静默跳过。

## 4. 配套铁律

- **未轮换的值严禁登记 `secret_history_allowlist.json`** —— 那是把红灯涂绿。
- 轮换后必须复核：`--compare-env` 显示在用值哈希**已与所有历史值不同**才算真换过。
- ⚠️ 残留边界：**"旧值在平台侧是否已失效"本机无法验证**，别把它写成已验证。

## 5. 可复用判据

> **比对两个"摘要"之前，先确认三件事：摘要算法、被摘要的对象、截断长度。**
> 三者任一不同，比对无效 —— 而它的失败方式是**给出相反结论**，不是报错。
> 能用工具固化的口径，就不要留在人手里。
