# git status 默认折叠未跟踪目录 → 漂移计数严重低估（run#39）

★升级候选

## 现象

统一巡检中枢回读器 sec5「git 漂移」连续多轮报"全仓 25 项"。
实际是 **63 项**，低估 2.5 倍。

根因：`git status --porcelain` **默认折叠未跟踪目录** —— 一个
`?? .workbuddy/memory/automations/` 藏住里面 **38 个文件**。

```
折叠（默认）: ?? 报 7 项
展开（-uall）: ?? 报 44 个文件  → 37 个被目录名隐藏
```

## 一般化规则

**凡用 `git status --porcelain` 做计数/审计/漂移检测，必须加
`--untracked-files=all`。** 折叠模式下"N 项"里的 N 是**目录项数**不是**文件数**，
两者可以差一个数量级。

判断信号：如果 `??` 里有**以 `/` 结尾或不含扩展名**的条目，就是被折叠的目录。

## 连带陷阱 1：聚合粒度选错 → 聚合彻底失效

展开后项数暴涨，自然会写"按目录聚合"。但**固定 depth 分组会静默失效**：

```python
# ❌ 错：路径 .workbuddy/memory/automations/<id>/memory.md 有 5 段，
#    depth=3 → key = ".../automations/<id>"，每个 id 各成一组且只有 1 项
#    → 全部落回「单文件原样打印」分支 → 38 行刷屏，聚合形同虚设
key = "/".join(parts[:3]) if len(parts) > 3 else p

# ✅ 对：depth=2 先粗聚；大组（>=10 项）再展开一层子目录 top3
key = "/".join(parts[:2]) if len(parts) > 2 else p
```

**纪律：写完聚合逻辑必须验证"聚合真的发生了"，不能只看代码里写了聚合。**
判据：输出行数应显著小于项数；若等于项数，就是退化成了逐条打印。
本轮正是靠场景 C 的断言 `输出行数 < 15` 才抓到这个（首轮 45 行 → 失败）。

## 连带陷阱 2：gitignore 规则路径 ≠ 实际写入路径

本轮同批发现两套 automations 记忆目录：

| 路径 | 磁盘文件 | tracked | gitignore 命中 |
|---|---|---|---|
| `.workbuddy/automations/*/memory.md` | 77 | 22 | ✅ 命中（但管不到已 tracked 的 22 个） |
| `.workbuddy/memory/automations/*/memory.md` | 38 | **0** | ❌ **无任何规则命中** |

规则写在旧路径，平台写在新路径 → 两边都不对。与 run#36「gitignore 重复 pattern」
同源：**gitignore 是典型的静默失效温床**，改了以为生效、其实没生效。

### ⚠️ 关键：修复方向有个反直觉陷阱

发现某路径"没被忽略"时，直觉反应是**补一条忽略规则**。这是错的——

- 不忽略 → `git status` 显示 `??` → **可见**，有被发现的机会
- 忽略 → `??` 都不显示 → **完全隐形**，盲区更深

**未入库 ≠ 有危险；隐形才是危险。** 正确处置取决于意图：
想保护就显式 `add`（本例 56.7KB，属设计决策，交用户定，未擅自入库）；
想忽略就要先确认"隐形"可接受。本轮只加了注释说明两套路径，
**一行规则都没动**。

## 连带陷阱 3：验证 gitignore 改动别用全量 check-ignore

`find . -type f | xargs git check-ignore -v` 在本仓要跑 **4.5 分钟**（26467 行），
且 `git check-ignore -v --stdin` 在 macOS git 下**返回 0 行**（不可用于批量，
实测空输出，会让人误以为"没有任何文件被忽略"）。

**更快更本质的做法：直接比对规则集合本身。**

```bash
grep -vE '^\s*(#|$)' .gitignore | sed 's/#.*$//' | sed 's/[[:space:]]*$//' | sort
```

加注释/调顺序这类改动 → 非注释行集合不变 → **忽略语义必然不变**，
比逐文件 check-ignore 严格且快 3 个数量级。再配 4 条关键路径抽样
`check-ignore -v`（输出须先 `sed -E 's/\.gitignore:[0-9]+:/.gitignore:N:/'`
归一化行号，见 run#36）即可。

## 复现的旧教训

**断言失败先检查断言本身**（run#38 已固化，本轮第 2 次复现）：首轮 6 项失败里
**3 项是验证脚本自己写错** ——
① 场景 A 断言"合计 4"但 `build()` 只 commit 未修改 → modified 实为 0；
② 场景 D 只放了 1 个未跟踪文件 → 折叠/展开都是 1，**根本不产生低估**；
③ 场景 C 断言按错误的 depth=3 粒度写。
**造故障条件时必须确认故障真的被造出来了**（B1/C1 这类"前置条件成立"断言就是为此）。
