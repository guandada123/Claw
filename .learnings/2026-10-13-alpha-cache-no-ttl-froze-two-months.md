# ★候选铁律 —— 「连续19天零差异」不是稳定，是缓存冻住了：无 TTL 缓存让下游静默跑了两月旧数据

**日期**：2026-10-13（Alpha101 因子评估自动化 automation-1786666500469）
**等级**：P0（**数据正确性**——两个月的因子评估/因子清单建立在两月前的 OHLCV 上，且被误读为"稳定"）
**类型**：data-integrity / silent-stale-downstream（无 TTL 缓存 → 下游静默产出旧结论）
**状态**：代码已由 10-13 的 TTL 补丁修复；**本文补充的是"误读口径"与监控缺口**。

---

## 1. 现象

同一个自动化 `alpha_eval.py --sample 300` 连续 **19 个"交易日"** 输出**逐字节相同**的结果
（24/24 因子零差异，kept 恒为 `[alpha5, alpha11, alpha15]`）。

我（历次执行记录）把这件事写成：

> 校验: 与上一日报告逐因子对比 **24/24 零差异**（已连续19个交易日稳定）

**"稳定"这个词本身就是误判。** 真实含义是：**输入没有变**。

## 2. 取证

| 检查项 | 结果 |
|---|---|
| `bars_*.csv` 缓存 mtime | 🔴 全部停在 **2026-08-13/14**（约 60 天前），1861 个文件 |
| `universe.json` mtime | 🔴 同为 08-13 |
| `cache_bars()` 旧实现 | 🔴 `if csvf.exists(): return _read_bars_csv(csvf)` —— **无 TTL，文件存在即返回** |
| 报告 `n_days` | 冻结在 **630**；10-13 刷新后 **668**（≈38 个交易日，与 08-14→10-13 吻合） |
| 24 因子指标 | 10-13 刷新后 **24/24 全部变化**（此前 19 天一个都没变） |
| kept 清单 | `[alpha5, alpha11, alpha15]` → **`[alpha5, alpha15]`**（alpha11 ICIR 0.364→0.285，跌破 0.3 保留线） |

→ 结论：**8-13 之后的所有评估都不曾真正重算过**。`n_days=630` 恒定就是最直接的指纹——
只要在算新数据，`n_days` 每天必然 +1。

## 3. 根因

```
无 TTL 缓存（文件存在即返回）
  → bars/universe 永不回源
  → 因子层、评估层、任何回测 静默使用两月前数据
  → 输出逐字节稳定
  → 被读成「清单稳定、链路正常」← 误判发生在这里
```

即既有铁律 **「上游定时任务失败 → 下游静默产出旧结论」** 的另一种载体：
这次上游没"失败"，是**下游主动放弃了取数**。

## 4. 教训（待周度升级为铁律）

1. 🔴 **「零差异」必须先证明是"输入未变"还是"输入已变但未被读取"**——
   看到恒定输出，第一动作是找一个**必然随时间单调变化的字段**（这里是 `n_days`）来反证。
   `n_days` 没涨 = 数据没换，而不是"市场很稳定"。
2. 🔴 **缓存必须有 TTL，且过期回源失败要"可见降级"**（WARNING 而非静默用旧值）。
   本次补丁已按此实现（`BARS_CACHE_TTL_HOURS=24` / `UNIVERSE_CACHE_TTL_HOURS=168`）。
3. 🔴 **凡"每日跑、结果恒定"的自动化，都该有一条独立的陈旧度监控**——
   不能靠人肉读日报发现。判据要来自**库外**（数据最后交易日 vs 交易日历），
   不能用"文件存在/报告已生成"这类自证。
4. 🔴 **报告里要落一个"数据新鲜度"字段**（如 `data_asof`），
   否则报告本身无法自证它算的是哪天的数据 —— 本次报告只有 `n_stocks/horizon`，缺 `data_asof`。
5. ⚠️ 本次是**先改成 TTL、再由自然运行消化存量**（不手工删缓存），这个处置顺序是对的：
   手工删 1861 个文件会撞 safe-delete 护栏（见 `2026-10-13-bulk-delete-trips-safe-delete-guard.md`）。
