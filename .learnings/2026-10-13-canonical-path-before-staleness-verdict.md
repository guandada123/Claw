## 3. 根因

本仓数据目录曾发生迁移（`data/` ↔ `.workbuddy/data/`），**旧位置保留了 Sep 23 的同名残片**，与新位置的正典产物并存数月。任何按「find 首个匹配 → 看 mtime」的排查（人/LLM 皆然）都会被残片带偏。

## 4. 教训（待周度升级为铁律）

1. 🔴 **判「某产物是否陈旧」前，必须先确定 canonical 路径——消费方读哪里，哪里才是真源**；
   多路径并存时，先 grep 消费方代码（`grep -rn "产物名" --include="*.py"`）再比 mtime。
2. 🔴 **目录迁移必须做「旧位置收尾」**：迁移脚本的最后一步应包含
   「旧路径残留归档/删除 + README 指路」，否则残片会长期伪装成"停更的真产物"。
3. ⚠️ **LLM 自动化会话的「调试模式」也是受害者信号**：当自动化放弃执行转而调研时，
   先怀疑它看到了什么矛盾信息（本例=残档），而不只是责备上下文漂移。
