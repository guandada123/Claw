# 固定回溯窗口会「老过」证据，导致判据静默退化且永不自愈

**日期**：2026-09-08（统一巡检中枢 run#115）
**分级**：P1（诊断误导，非服务中断）
**状态**：已修复并验证
★升级候选

## 现象

run#114（2026-09-08 12:11Z）微信通道告警文案 =
「登录过期，但**通道早于过期即停摆，重登大概率无法恢复**，建议摘除该巡检项或确认上游调用方；
上游RSS同步已停止调度(PAUSED)，落盘停在 2026-08-13」

run#115（2026-09-08 15:15Z，仅 3 小时后）同一检查项文案退化为
「登录过期(isExpired=true)，**需扫码重登**」——且这条被真实推送到飞书。

代码自身的 docstring 明确写着「此时提示"扫码重登"**会误导**」。
即：检查项退化成了给出它自己判定为错误的处置建议。

## 根因

`_container_last_fetch_ts()` 用**固定** `docker logs --since 1200h`（50 天）回溯窗口，
去找容器最后一次真实抓取 `[Fetch]` 的时点。

- 最后一条 `[Fetch]` = `2026-07-20T14:19:10Z`（通道 50 天前就停摆了）
- 09-08 15:16Z 的窗口起点 = `2026-07-20T15:16:45Z`

**证据比窗口起点老 57 分钟。** 实测：

```
--since 1200h  → [Fetch] 命中 0 条
--since 1300h  → [Fetch] 命中 358 条
```

于是函数返回 `None` → 上层判据 `(exp_dt - last_fetch).days >= 1` 落空 →
退到 `else` 分支输出误导文案，同时丢掉「抓取早于过期 33 天停摆」+ 上游 RSS 实况这些诊断上下文。

**关键性质：墙钟单向推进，窗口只会越滚越远 → 该退化永不自愈。**
run#114 还是对的、run#115 就错了，中间没有任何代码变更或人为动作，纯粹被时间推过临界点。

## 修复

`unified_ops_center.py`：
1. 窗口 `1200h` → `2400h`（100 天），把临界点推远；
2. **落盘锚点持久化** `.wechat_last_fetch_anchor.json`：一旦观测到就永久记住，
   取 `max(日志观测, 锚点缓存)`，**单调只前进**。证据滚出日志窗口后判定依然成立。

组合行为推演（run#54 纪律⑦：改判据必须显式推演叠加行为）：
- 通道持续死 → 锚点恒为 07-20，enriched 分支稳定，文案稳定；
- 通道日后恢复抓取 → 新 `[Fetch]` 时点更大 → 推进锚点 → `days < 1` → 回到 `else` 分支，
  此时「扫码重登」**才是正确建议**。闭合，无死锁。

验证：`ruff` 0 违规；Claw 测试 **501 passed**；
模拟 `since='1h'`（窗口彻底滚过）仍返回 07-20 14:19Z（锚点兜底生效、单调未回退）；
`--dry-run` 端到端确认 enriched 文案与诊断 note 已恢复。

## 可迁移铁律

1. **任何 `--since` / `--tail` / 固定窗口的取证型判据，都自带一个"过期日"。**
   窗口是相对当下的，证据是绝对时间点的 —— 两者必然在某天交叉。
2. **一次性取证结论必须落盘锚点，不能每轮重新从易失源（容器日志/滚动窗口）推导。**
   易失源 + 固定窗口 = 定时炸弹。本仓已有先例（`.qts_api_auth_401_anchor.json`），本次是同一模式第二次应用。
3. **排查「昨天对今天错、中间无变更」的现象，第一嫌疑就是相对时间窗漂移**，
   不要先去找代码变更或外部故障。
4. 判断退化，用**同一命令换窗口宽度对拍**（1200h vs 1300h）即可零成本定位，
   比读代码猜快得多。
